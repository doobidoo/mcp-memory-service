- **The scheduled harvest tracker distinguishes retryable failures from completed zero-candidate sessions (R7).** A session that stored nothing used to be recorded as harvested and skipped forever. Now `sessions_to_track()` tracks a session when it stored something (`stored>0`) or had nothing to harvest at all (`found==0`, deterministic zero-candidate), and leaves it pending only for a retryable failure (`found>0 and stored==0`, e.g. the LLM chain was down). This re-harvests transient failures without letting permanently-empty sessions starve older pending ones.
