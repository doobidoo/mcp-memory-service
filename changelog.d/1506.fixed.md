- **A hybrid hub forwards the delta-sync events it applies to its secondary (#1506).**
  `apply_remote_event` writes the primary's SQLite directly, so a create, edit or delete a
  spoke pushed to a hybrid hub never reached the sync queue and Cloudflare held only the
  hub's own writes. Each sync cycle now tails `sync_events` from a persisted cursor (a
  `push_cursor` row), so a restart or an unreachable secondary loses nothing, and brings the
  secondary's copy of each touched memory in line with the hub, in the memory's own store.
  A change the secondary already holds is skipped, and an edit carries the hub's own
  `updated_at`, so a forwarded edit or delete is not
  applied again when the hub next compares with the secondary.
