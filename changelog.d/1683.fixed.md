- **Store-scoped operations stay within the requested memory store (#1683).** Search, on-store NLI, hash-addressed writes, entity-graph reads, bootstrap profiles, MCP resources, auto-capture evolution, and SQLite conflict detection carry the store through storage predicates; scoped NLI quarantines/counts only within that store and does not mutate unpartitioned global belief state. Backends without proven partition support fail closed instead of exposing data from another store. Named-store HTTP sync fails closed until the hub advertises store-scoped access, so upgrading only the client is not sufficient. Store-scoped analytics omit the backend-wide database file size; the global all-store view retains it. Milvus graph reads remain unavailable to scoped grants until graph edges carry store ownership.
