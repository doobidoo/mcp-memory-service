- **Store-scoped metadata updates are confined in the storage layer (#1875, part of #1683).** `update_memory_metadata` and `update_memory_versioned` looked a memory up by `content_hash` alone. A claim on one store was only enforced by a `get_by_hash` pre-check in the MCP handler, so the check and the write were two separate steps. Both methods now take `store`, put `AND store = ?` into the lookup and the `UPDATE`, and report a memory in another store as not found without changing it. The MCP handler and `PUT /api/memories/{hash}` pass the claimed store through. `None` and `"all"` stay unscoped, so callers without a store behave as before. sqlite-vec and hybrid only; the other backends still refuse store-scoped updates until #1878 and #1879 land.
