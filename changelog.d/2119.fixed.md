- **Milvus graph: edges carry the store, and entity reads honour it (#2119, part of #1880).** The association collection is separate from the memories, so unlike the SQLite graph (#2118) it cannot join to find out which partition an edge belongs to — and nobody who writes an edge knows it, because `Memory` carries no store and the call sites hold only the hash. The collection now has a `store` field (`VARCHAR`, `default_value="default"`, INVERTED index), and the backend resolves the store from the paired memory collection when it writes an entity link or an association. Cross-store association pairs and links for unknown memories are refused rather than stamped into a partition they do not belong to. `list_entities`, `get_entity_profile`, `find_memories_by_entity`, `get_entities_for_memory` and `common_neighbors` filter on it, `None` and `"all"` stay unscoped. A collection created before the field has nothing to confine on, so a named store is refused there until it is recreated — the same decision as #1879 on the memory collection.
