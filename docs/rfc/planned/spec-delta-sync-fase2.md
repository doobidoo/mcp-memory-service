- **Escopo:** APENAS Fase 2 (ainda LOCAL, sem transporte/rede — isso é Fase 4).

## Requisitos cobertos (rastreabilidade)
- **R3 / R3'** (reconciliação determinística por ordem lógica + importância só em empate) — núcleo.
- **§8.2** (HLC + tie-breaker estável + resolver reproduzível) — critérios de aceite.
- Depende de: Fase 1 (tabela `sync_events`, helper `_append_sync_event`). NÃO cobre: transporte (Fase 4), embedding consistency §8.3 (Fase 3), shareable §8.4/cursor §8.5 (Fases 4-5).

## Requisitos funcionais (EARS)

**F1 — HLC em cada evento**
> WHEN an event is appended, THE storage SHALL stamp a Hybrid Logical Clock as `(hlc_physical, hlc_logical)`, generated by the canonical send/local rule, in the SAME transaction as the event (ADR-0008/0010).

**F2 — clock monotônico persistente**
> WHILE events are appended, THE storage SHALL persist `last_hlc` in `metadata` and never let the clock regress across restarts (ADR-0011).

**F3 — ordem canônica**
> WHEN events are ordered, THE system SHALL order them by `(hlc_physical, hlc_logical, agent_id, event_id)`, a total order (ADR-0010).

**F4 — resolver determinístico e comutativo**
> WHEN two concurrent events for the same `content_hash` are reconciled, THE resolver SHALL return the same winner regardless of input order (`resolve(a,b) == resolve(b,a)`), using: logical order → delete-vs-update (delete wins on `hlc(delete) >= hlc(update)`) → importance on exact logical tie → `agent_id`/`event_id` final tie-break (ADR-0012/0013).

**F5 — late event não sobrescreve**
> WHEN an event arrives with an HLC lower than the already-applied state for its hash, THE apply step SHALL record the event (audit/idempotency) but SHALL NOT overwrite the materialized winner.

**F6 — importância só em empate lógico exato**
> WHERE two events have identical `(hlc_physical, hlc_logical)`, THE resolver SHALL use `quality_score` to break the tie, and ONLY then (ADR-0013).

**F7 — resolver puro**
> THE resolver SHALL be a pure function (no I/O, no clock, no network), testable in isolation.

## Requisitos não-funcionais
- **NF1** migração `016_add_hlc_to_sync_events.sql`: ADD COLUMN hlc_physical/hlc_logical + índice `(hlc_physical, hlc_logical, agent_id, event_id)` + backfill Phase 1 (`created_at*1000`, `seq`). Aditiva, idempotente (WHERE hlc_physical IS NULL), `.down.sql` documental.
- **NF2** `_append_sync_event` muda internamente (calcula+persiste HLC); assinatura inalterada; os 4 call-sites da Fase 1 NÃO mudam.
- **NF3** resolver vive em módulo novo `storage/sync/resolver.py` (puro).
- **NF4** retrocompat: eventos Fase 1 ganham HLC via backfill; kill-switch `MCP_SYNC_EVENTLOG` inalterado.

## Critérios de aceite (= fixtures §8.2, viram testes RED no Gate 2)
- [ ] **CA1 (F4 convergência)** 2 eventos concorrentes mesmo hash (agent A, B) → `reduce_events([a,b]) == reduce_events([b,a])` (mesmo vencedor).
- [ ] **CA2 (F5 late event)** evento com HLC < applied_hlc → registrado, estado materializado inalterado.
- [ ] **CA3 (F6 importância)** 2 updates com `(hlc_physical,hlc_logical)` idênticos, quality 0.9 vs 0.3 → vence 0.9.
- [ ] **CA3' (empate total)** mesmo HLC + mesma quality → vence menor `event_id` (determinístico).
- [ ] **CA4 (F4 delete-vs-update)** delete hlc=(100,0) vs update hlc=(100,0) → delete vence; update hlc=(101,0) → update vence.
- [ ] **CA5 (F1/F2 HLC monotônico)** N stores → HLC estritamente crescente em `(physical, logical)`; `last_hlc` em metadata reflete o último; não regride após "restart" (reabrir storage).
- [ ] **CA6 (NF1 backfill)** eventos Fase 1 (sem HLC) após migração 016 → `hlc_physical = created_at*1000`, `hlc_logical = seq`, nenhum NULL.
- [ ] **CA7 (§8.1c ponte)** tombstone + replay de create antigo → create NÃO ressuscita (invariante de apply, consistente com resolver).

## E2E a quente (fecha a fase, ambiente real)
1. `MCP_SYNC_EVENTLOG=on`: store de N memórias → conferir HLC crescente em `sync_events`, `last_hlc` em metadata avançando.
2. Simular 2 "hosts" (2 DBs locais) com eventos concorrentes sobre o mesmo hash → aplicar em ordens trocadas → mesmo estado final (convergência).
3. Reabrir o storage (restart) + novo store → HLC continua de onde parou (não regride).
