    What's new in v11.15

    94 commits since the previous release, 4,128 tests.

    • Security

      mcp-memory-server refuses a non-loopback bind

      It used to serve the full MCP tool surface with no authentication on whatever address MCP_HTTP_HOST named. Network clients now use memory server --streamable-http with MCP_API_KEY or OAuth. GHSA-26rx-6fvr-qjqg, reported by @NotAFlightRisk.

    • API

      Scope memory and search by store

      The HTTP API scopes memory, search, CRUD and analytics by store, and POST /api/search/by-tag accepts a limit. Milvus now implements the full storage and graph contract.

    • Retention and search

      Long-standing correctness fixes

      A human rating no longer overwrites the machine quality score that retention reads, MCP_DECAY_ENABLED=false takes effect, hybrid BM25 matches keywords, and exact-mode search no longer treats % and _ as wildcards.

    In the wild

    Three deployments people built and run themselves.

    "After I work with one of the cluster agents on something I want my local agent to know about, the cluster agent adds a special tag to the memory entry that my local agent recognizes as a message from a cluster agent. So they end up using it as a comms bridge, and it's pretty delightful."
    @jeremykoerber

    A five-agent cluster uses one memory service as shared state and as an inter-agent channel, with no custom protocol: cluster agents write a sentinel tag, the local agent filters on it. The pattern

    "File-based memory demands constant discipline. Semantic recall from a live database doesn't. Storing data on my own hardware while making it remotely accessible across platforms turned out to be a feature I didn't know I needed."
    @PL-Peter

    Two Docker containers on one SQLite backend, a Cloudflare tunnel for name-based routing, and an auth gateway in front. The checklist

    "Claude Code, Claude Desktop, Codex CLI and OpenCode all talk to the same sqlite-vec DB over stdio on my Mac. ~5,900 memories and counting. It's the closest thing to persistent identity my agents have."
    Mingjian Shao, AI PM and consultant, September 2026

    One local sqlite-vec database shared by four agents: no server, no cloud, offline embeddings, daily backups and scheduled consolidation.

    Why the benchmark gap? MemPalace stores whole sessions as single units, and LongMemEval asks which session contains the answer, so that granularity answers the question structurally. This service defaults to turn-level storage for finer retrieval; session-mode ingestion brings it to 86.0% R@5.
    1 Measured in MemPalace "raw mode": plain text in ChromaDB with default embeddings. Per Issue #27, the Palace structural features are bypassed in that configuration, and the maintainers acknowledged most of the review's points.
    2 Uses optional LLM reranking (~500 API calls) on a partially tuned test set. Clean held-out score as reported by the maintainers: 98.4% R@5.

    SHODH ecosystem

    Fully compatible with the SHODH Unified Memory API Specification: every SHODH implementation shares the same memory schema (emotional metadata, episodic memory, source tracking, quality scoring), so memories export and import across implementations with full fidelity. The reference implementation is shodh-memory (RocksDB); shodh-cloudflare runs on Workers + Vectorize; this service runs SQLite-vec or Hybrid.
