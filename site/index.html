What it is

MCP Memory Service is an open-source server that gives AI agents a memory that outlives the session. Agents and assistants forget everything when a conversation ends; this service stores what they learned on your own machine or server and hands it back when it is relevant. It is built for developers who work with coding agents, and for teams that run several agents on shared knowledge.

  1. Persistent memory

    A client stores a decision, a fix or a preference as a memory with tags and a type. It stays in a database you control: SQLite-vec on disk by default, Cloudflare, a hybrid of both, or Milvus.

  2. Semantic search

    By default each memory is embedded by a local ONNX model, so a later question finds it by meaning even when the wording differs. Hybrid search adds BM25 keyword matching to the vector results; tags and time ranges narrow them.

  3. Knowledge graph

    Memories are linked by typed relationships such as causes, fixes, contradicts and supports. Scheduled consolidation lets stale entries decay and compresses related ones.

What's new in v12.9

The ontology overlay gets a REST API, a dashboard section and sync between nodes, and two access-scope leaks are closed.

  • Ontology

    REST API and dashboard section

    GET /api/ontology returns the merged memory types, relationships, type patterns and retention periods. Writes go through the same validated storage methods and need the global write scope.

  • Sync

    The ontology overlay syncs through the hub

    Overlay writes become sync events that peers resolve per key. A peer that does not advertise ontology_sync keeps syncing memories without stalling.

  • Security

    MCP prompts and server status respect scope

    prompts/get now requires a global read scope, and /api/server/status returns process, OS and Python details to admin callers only.

  • Dashboard

    Tag management minimum-use filter

    Tag management hides tags used fewer than twice by default, with an adjustable threshold. The disabled System Maintenance placeholders are gone.

  • Search

    Recall ranges keep both ends

    "From January to March" now parses as the whole window instead of keeping only the start.

SHODH ecosystem

Fully compatible with the SHODH Unified Memory API Specification: every SHODH implementation shares the same memory schema (emotional metadata, episodic memory, source tracking, quality scoring), so memories export and import across implementations with full fidelity. The reference implementation is shodh-memory (RocksDB); shodh-cloudflare runs on Workers + Vectorize; this service runs SQLite-vec or Hybrid.

Questions

What it stores, where the data lives, and where the limits are.

Does it save every conversation automatically?

No. Connecting the service over MCP gives your client tools to store and recall memories; the client has to call them. Optional hooks for Claude Code and a session import have their own setup.

Where is my data stored?

With the default SQLite-vec backend, memories and their embeddings live in a database file on the machine that runs the service, and embeddings are computed there. The embedding model is downloaded once on first start. Cloudflare storage, hybrid sync and Milvus are optional backends you configure yourself. What your AI client sends to its own model provider is up to that client.

Which clients and frameworks work with it?

Any MCP client over stdio, such as Claude Code, Claude Desktop, Codex CLI, Cursor, OpenCode, Gemini CLI, VS Code, Windsurf and Zed. Browser chat apps such as claude.ai and ChatGPT (Developer Mode) connect over Remote MCP with OAuth 2.1. Frameworks such as LangGraph, CrewAI and AutoGen use the REST API. The integrations list has the details.

How do I install and run it?

Install with pip install "mcp-memory-service[sqlite]" on Python 3.11 or newer, then add it to your client, for example claude mcp add memory -- memory server for Claude Code. The same package runs the HTTP server with the REST API, the dashboard and Remote MCP. The setup guide walks through it.

Is it free?

The software is open source under Apache 2.0 and has no license fee. You run it yourself, so hosting, your AI client's subscription or API usage, and any optional external service such as Cloudflare are your own costs.

What are the limits?

It is a memory store, not a model: it does not answer questions, it returns the memories that match. Search quality depends on the embedding model, and changing its dimensions means re-embedding every memory. External embedding APIs are supported on the SQLite-vec backend only.
